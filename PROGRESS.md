**Epic 0009 (linked-diagram navigation) implemented, bug found and fixed during your manual test (2026-08-19)** — the last of the "complete PoC" batch, on branch `epic/0009-linked-diagram-navigation`. Ctrl/Cmd+click on a node with no link shows a chooser (create new / link existing, reusing the existing context-menu popup); an already-linked node navigates straight in. Missing/unreadable links show a clear alert without disturbing the current diagram. Breadcrumb trail in the toolbar for back-navigation. Right-click gained "Link to diagram…" / "Open linked diagram" / "Remove link". Required explicitly pinning React Flow's `multiSelectionKeyCode` to `"Shift"` (collided with Ctrl/Cmd otherwise).

Your test found a real bug: the link was set in React state and then immediately navigated away from, before the parent was ever written to disk — the link was lost every time, not occasionally. Fixed by adding `persistDiagram` (the one place a diagram gets written) and calling it, with the link change computed directly rather than via `updateNodeData` timing, before any forward link navigation — creating, picking existing, or Ctrl+clicking an already-linked node. `performSave` now goes through the same function. Also changed per your feedback: "Link to existing diagram…" no longer navigates after linking (stays put); "Create new" still does. A tabs/multi-window idea came up as a possible fix during testing — deliberately not adopted here, since the actual bug had a small complete fix; multi-window/tabs is a legitimate but much bigger idea worth its own future epic. `npm run typecheck`/`lint` clean, app launches — still needs your re-test to confirm the fix holds before merging.

**Custom metadata bucket scoped, not started (2026-08-19)** — [ADR 0009](docs/decisions/0009-custom-metadata-bucket.md) + [epic 0023](docs/planning/epics/0023-custom-metadata-bucket.md). A free-form JSON `metadata` field on nodes/edges/diagrams, separate from the tool's own standard fields, editable via a raw JSON textarea in the GUI and guaranteed to round-trip through open/save — closes a real gap found while discussing epic 0022 (today, any field outside the documented schema is silently dropped the instant a file is opened, before any edit).

**Styling panel (epic 0003) expanded with named/searchable style presets (2026-08-19)** — [ADR 0010](docs/decisions/0010-named-searchable-style-presets.md). Edge line/marker styles (and shape fill/border) get a right-click-accessible catalog of industry-standard named presets ("Dependency (UML)", "One-to-many (ERD)"), searchable by keyword like the existing icon picker — an educational aid for novices, not an enforced notation. Presets apply raw style properties only; nothing is stored as a preset "identity" on the element itself. Epic 0013 (connection points) got a note distinguishing it from this — placement vs. visual marker styling are separate concerns that surfaced in the same conversation.
