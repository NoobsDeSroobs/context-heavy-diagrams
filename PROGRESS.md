## Design session outcome (2026-08-20)

Starting epic 0021 (detail frontmatter) triggered a real design conversation instead: frontmatter's motivations turned out to already overlap with two other planned-but-unimplemented epics (0023's metadata bucket, 0026's tagging). Working through *why* they should or shouldn't be separate mechanisms produced a unified design — one `data.metadata` field per Shape/Container/Edge, entries either free (human-added) or diagram-required (a template with optional validation/lock), with retroactive backfill and a new non-blocking diagnostics panel for when that backfill has to reset something. Full reasoning in [ADR 0022](docs/decisions/0022-unified-tag-and-metadata-system.md) (supersedes [ADR 0009](docs/decisions/0009-custom-metadata-bucket.md)); implementation checklist in [epic 0034](docs/planning/epics/0034-unified-tag-and-metadata-system.md). Epic 0021 is retired, epic 0023 is superseded, epic 0026's tag-storage design now points at 0034 instead of its own original `data.tags: string[]` sketch. Not yet implemented — this was pure design/scoping, no code written.

## Epic 0024 implemented, awaiting your review (2026-08-20)

Design conversation resolved the epic's open question — separate `BrowserWindow`s per diagram, not tabs — see [ADR 0023](docs/decisions/0023-multi-window-diagram-model.md) for why (the stated goal needs simultaneous visibility, which tabs alone don't provide, and the codebase was already shaped for one-diagram-per-renderer so windows were close to free). Also decided along the way: File → New/Open and both linked-diagram navigation flows (create new, follow existing) now always open a new window rather than replacing the current one; a duplicate-window guard focuses an already-open window instead of opening the same file twice. This retires breadcrumb back-navigation from epic 0009 as dead code. Full implementation is done — see [epic 0024](docs/planning/epics/0024-multi-diagram-tabs-or-windows.md) for the task-by-task detail — `npm run typecheck`/`lint` both clean, but not yet click-through tested (couldn't be verified via the Browser pane; this is a real multi-window Electron feature). Branch: `epic/0024-multi-diagram-windows`, not yet merged.

## Epic 0035 implemented, awaiting your review (2026-08-20)

Raised directly by the user while reviewing/testing epic 0024: a "Copy to children" button on the Required Tags panel, pushing the current diagram's `requiredTags` template down its whole link subtree so a complex view doesn't need the same tags redefined by hand in every sub-diagram. Design in [ADR 0024](docs/decisions/0024-propagate-required-tags-to-children.md): merge (parent wins on key collision, a child's own extra tags survive), recurse the whole subtree with a pre-write preview/confirmation, and — flagged by the user mid-design — never cross outside the current diagram's own directory tree, since a link can legitimately point at an externally-owned diagram (ADR 0005) that this operation must not reach into. Full implementation done — see [epic 0035](docs/planning/epics/0035-propagate-required-tags-to-children.md). `npm run typecheck`/`lint` clean. Branch `epic/0035-propagate-required-tags-to-children` **stacks on top of the not-yet-merged `epic/0024-multi-diagram-windows`** (touches the same few files — `index.ts`, both preload files, `Canvas.tsx` — so it was branched from there rather than master); merge 0024 first, then 0035.
