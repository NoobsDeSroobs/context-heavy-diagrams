- **Unrelated bug fixed on the same branch, 2026-08-24**: live-testing epic 0032 surfaced a pre-existing bug, reproduced on `master` too — opening the Meridian Rail landscape (82 nodes/84 edges, the largest gallery diagram) showed zero edges, broken drag-to-select, and no new-connection dragging, all from a React Flow node-measurement race that could fail to settle on its own at that scale. See [known-issues.md](docs/known-issues.md#a-large-diagrams-edges-selection-box-and-new-connection-dragging-all-silently-failed-until-node-measurement-happened-to-catch-up) for the full root cause. Fixed in `loadDiagramIntoCanvas` (`Canvas.tsx`) by forcing `updateNodeInternals` for every node right after load instead of relying on passive `ResizeObserver` timing. Live-confirmed by the user on the same file. `typecheck`/`lint` clean (no new issues vs. baseline).
- **Follow-on performance issue found live-testing the fix above, only partially resolved, 2026-08-24**: drag-to-select still stutters ~300ms per boundary crossing on this same large diagram; isolated to merely *hovering one edge* causing every node/edge to re-render several times over. Two real, confirmed causes fixed (stale wrapper-object identity for nodes/edges; several inline props — `onEdgeMouseEnter`/`onEdgeMouseLeave`/`defaultEdgeOptions` — recreated every render, one of which React Flow reads via an unguarded, uncompared store subscription) but neither moved the actual render counts, so a dominant, still-unidentified cause remains. Left **open** at the user's call rather than continuing via `console.count` instrumentation (diminishing returns after several rounds) — see [known-issues.md](docs/known-issues.md#hovering-a-single-edge-on-a-large-diagram-re-renders-every-node-and-edge-several-times-over) for the full investigation and the recommended next step (React DevTools Profiler). `typecheck`/`lint` clean.
