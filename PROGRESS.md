## Next up

**Epic 0004 (containers) implemented and merged 2026-08-19** (PR #12). `ContainerNode`, `parentId` schema field, drag-into/out-of-container reparenting, container-delete-promotes-children, "Attach contained shapes" bulk action, `crypto.randomUUID()`-based node ids. Full detail and the handful of user-reported bugs fixed along the way are in [epic 0004's own doc](docs/planning/epics/0004-containers.md) — not duplicated here.

**Epic 0003 (styling panel) implemented, verified, and merged 2026-08-19** (PR #13). `NodeStyle`/`EdgeStyle` schema, the two-slot dock layout (ADR 0013), item palette, property panel, live style rendering on all four node/edge types (including hand-drawn SVG markers), and the right-click Fill…/Border…/Line style… pickers (ADR 0010). User review caught and fixed several real gaps along the way (`fontFamily` and per-channel `opacity` missing from the schema, container z-order, an opacity-field UI bug, container default fill) — full detail in [epic 0003's own doc](docs/planning/epics/0003-styling-panel.md).

**Epic 0011 (alignment and snapping) implemented, fixed, and merged 2026-08-19** (PR #14). Drag-time alignment guides + 5px proximity snap-to-shape (screen pixels, not canvas units) against every other node's left/center/right and top/center/bottom, independently per axis. No snap-to-grid (decided out) and no connection-aware alignment (split out to [epic 0031](docs/planning/epics/0031-connection-aware-alignment.md) — see epic 0011's own doc for why). User testing after implementing caught a real bug — snap held while dragging but reverted the instant the mouse was released, root-caused to React Flow committing its own raw-position update immediately before `onNodeDragStop` fires — fixed same session. Full detail in [epic 0011's own doc](docs/planning/epics/0011-alignment-and-snapping.md)'s Implementation notes.

**Bug fix (branch `fix/container-delete-cascade`, not yet merged): deleting a container was deleting all its contained shapes instead of promoting them.** Found by the user right after merging epics 0003/0011, but the root cause predates both — epic 0004's own doc had already flagged this exact scenario ("container deletion actually promoting a real child") as never interactively confirmed. React Flow's own delete handling cascades a remove-change to every descendant automatically; epic 0004's original guard only ever stripped the container's own remove-change, never its children's. Fixed to walk the full descendant chain. See [epic 0004's doc](docs/planning/epics/0004-containers.md)'s Notes for the full writeup — **needs a manual verify-and-merge**, same live-interaction-testing gap as everything drag-related in this project.
