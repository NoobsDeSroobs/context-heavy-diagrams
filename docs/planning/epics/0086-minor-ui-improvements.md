# 0086: Minor UI improvements

## Status
In Progress — one of four items done (zoom-out limit), three still open

## Goal
Grab-bag epic for small, low-effort UI/UX improvements that come up during regular use — each individually too small to justify its own epic, collected here and picked off as convenient.

## Tasks
- [ ] Remember property panel section collapse state per session — closing e.g. "Transform" on one shape should keep it closed when selecting a different shape/edge/container, for the rest of the app session (no persistence to disk needed). `CollapsibleSection` (`src/renderer/src/panels/fields.tsx`) currently holds open/closed as local `useState`, reset on every remount. Fix: move it to a shared, module-level `Record<string, boolean>` keyed by a stable section key, read/written by `CollapsibleSection` instead of local state. Needs a `sectionKey` prop distinct from the display `title` for the handful of callers whose title is dynamic (`` `Allowed values (${n})` `` in `RequiredTagsPanel.tsx`, `` `Colors (${n})` ``/`` `Fonts (${n})` `` in `StylePalettePanel.tsx`, the per-type multi-select group headers in `PropertyPanel.tsx`) — those can't key off the literal title since it changes with the count. Estimated small (~15-20 min), one function plus a handful of one-line call-site updates.
- [ ] `step`/`smoothstep` routing styles offer no way to drag a segment into position — only `catmullRom` routing supports manual bend points today (`LabeledEdge.tsx`'s bend-point handles are gated on `routingStyle === 'catmullRom'`, see line ~331; `step`/`smoothstep` paths are fully computed by React Flow's own `getSmoothStepPath` with no interior points at all, epic 0032). Reported live: the user wants to be able to pull a step/smoothstep edge's segments into position the way catmull-rom bend points already work, citing React Flow's own "Editable Edge" doc example (`reactflow.dev/examples/edges/editable-edge`) as having this built in. **Checked (2026-08-24, WebSearch/WebFetch)**: that example is real, but (a) it's a **Pro-only example** (React Flow Pro subscription, no source given), and (b) per xyflow's own description, draggable control points are **not a built-in capability of `getSmoothStepPath`/`getBezierPath`/etc.** — those core functions only compute a static path from source/target with no interior points at all; the Pro example is xyflow's own custom edge component layered on top, conceptually the same kind of thing this project already built for `catmullRom` (`bendablePath.ts`, epic 0032). So: confirmed genuinely possible (not a React Flow limitation blocking it), but not something to copy from React Flow directly — would need building this app's own orthogonal step-routing algorithm with real draggable interior points, parallel to the catmull-rom work but for right-angle segments instead of curves. **Flagging this is a bigger lift than the other items in this grab-bag epic, not a same-sized "minor" fix** — worth a real design pass before starting, not a drop-in.

- [ ] The icon picker's scrollbar partially covers the rightmost column of icons. `.icon-picker-scroll` (`main.css`) is the `overflow-y: auto` element wrapping `.icon-picker-grid`'s 6-column grid, but nothing reserves space for the scrollbar's own width — it renders on top of the grid's right edge instead of the grid narrowing to make room. Likely fix: add right padding to `.icon-picker-scroll` (and matching negative margin, or shrink the grid's own width) sized to the scrollbar, or use `scrollbar-gutter: stable` so the gutter is reserved whether or not the content is actually tall enough to scroll. Worth confirming which of this app's target OSes (Windows/Linux) actually show an overlay-vs-space-taking scrollbar by default before picking a fix, since that changes whether this reproduces everywhere or is Windows-specific.
- [x] Allow zooming out further than today's limit — and make it a real Setting, not a hardcoded value. Confirmed this app never set `minZoom`/`maxZoom` on `<ReactFlow>` at all — the `0.5`/`2` limits were purely React Flow's own unconfigured library defaults. Went through two rounds of user feedback: first pass hardcoded `minZoom={0.1}`, then made it a proper Setting (two new `AppSettings` fields, `src/shared/settings.ts`, defaults `0.1`/`2`), initially as two separate full-width `NumberField` rows — then the user asked for one compact row instead (`"Zoom limit: in [0.1] out[2.0]"`). Final shape: `ZoomLimitField` (new local component, `SettingsPanel.tsx`) — one `FieldRow` holding two small inline number inputs (own minimal draft-until-blur state, not `fields.tsx`'s `useDraft` since it isn't exported and this file's `react-refresh/only-export-components` rule means it should stay component-only). `Canvas.tsx`'s `<ReactFlow>` reads both from `settings`. No migration needed — `readAppSettings` already merges any missing field onto `DEFAULT_SETTINGS` for old settings files.
