# 0148: An assistant builds a diagram by operations that answer with what they made

## Status
Accepted (2026-11-06). Partly superseded by [0171](0171-an-edit-answers-with-the-problems-it-touched.md): an edit no longer repeats every layout problem. The set of operations has grown since the first version and is expected to grow again; the shape of an operation does not change.

## Context
Assistants asked to draw a large diagram wrote their own generator scripts, about a thousand lines each, to get ids, parent order, connection points and positions right. A script needs a runtime the machine may not have, and Claude Desktop with the extension has no shell at all.

## Decision
- **The assistant works the way a person does, in small steps, and each step answers with what it made.** The operations are add an entity, container, text or line; connect two elements; add a connection point; move, resize, relabel, restyle, nest and remove (which deletes an element with its edges, or an edge); set and remove tags, on an element, an edge and the diagram; set and remove the diagram's required tags, highlights and legend entries; link to an existing diagram, add a new linked diagram, remove a link, and set and remove a note; and set the routing points of an edge (all of them at once, an empty list clears them), warning when the edge's routing style would ignore them. They are plain data (`{ "op": "move", "id": "api", "x": 200, "y": 0 }`).
- **The assistant decides all layout.** The tool never places anything for it. It answers questions instead: how much room two connected elements need for a label ([ADR 0146](0146-elements-joined-by-an-edge-keep-a-gap-for-the-label.md)), the elements as they stand, and what is wrong with the layout so far (a label without room, overlapping elements, an element sticking out of its container, an edge running over an element).
- **One pure core in shared code,** `src/shared/edit/`: a function from a diagram and a list of operations to a new diagram and an answer per operation. A batch is all or nothing and an error names the operation. Coordinates are absolute in operations; the parent-relative form the file stores stays inside the core. The caller supplies the id generator, so the core stays free of Node.
- **The first executor works on the file, through the Claude Desktop extension's MCP tools** `edit_diagram`, `inspect_diagram` and `room_for_label`, so no shell is needed. `edit_diagram` creates the file if it does not exist; for a file that exists it needs the fingerprint of the last answer ([ADR 0109](0109-stale-edit-check-for-every-ai-write-path.md)) and writes through the same validated, atomic write as `create_file` and `update_file`. A diagram the server made in the current session may be edited again without the setting that allows changing existing files; any other existing file still needs that setting.
- **Because the operations are data and the core is pure,** the open window can later run the same operations on its live diagram as one undoable step; the questions already take a diagram and not a path.
- **Tags follow the editor.** A required tag is seeded on every new entity, container and edge and filled in on every existing one when the template changes, by the same code the editor runs (`src/shared/tagging/metadataSync.ts`, shared by both so they cannot drift); a locked value is checked and a fixed one refused. Elements, edges, highlights and legend entries are created with the editor's own defaults and field order, so the app reads the file back without a change.
- **A note is a file the executor writes.** The core never touches a disk: `set_note` stores the path of a new Markdown file beside the diagram and hands the text back to the caller as a file to write. The file executor creates it (never overwriting one that exists) before it writes the diagram, and removes it again if the diagram is refused. Changing an existing note is not an operation: it is a file the assistant reads and updates under the same fingerprint rule as any other. `remove_note` drops only the reference; no operation deletes a file.
- **A stored path stays inside the folder.** A link or note path is relative to the diagram, and the executor refuses one that leads outside the folder the assistant may use ([ADR 0115](0115-paths-stored-in-diagrams-are-untrusted.md)). A link to a diagram that does not exist yet is allowed and reported as a warning, so a parent can be built before its children. `add_new_linked_diagram` does what the editor's "new linked diagram" does ([ADR 0005](0005-diagram-identity-and-linking.md)): the child is named after the element and goes in the folder named after the parent, so a hierarchy nests one folder deeper per level instead of lying flat. It stores only the link (the core touches no disk); the assistant makes the child with `edit_diagram`, which makes the folder. `link_to_existing_diagram` stays for a diagram that already exists or is shared, and points to `add_new_linked_diagram` when the diagram it names does not exist and lies outside the parent's folder. The two names are the editor's two actions, so an assistant makes the same choice a person does.
- **Answers are short, because a build is mostly answers.** An operation names the element it touched by its id, and after a geometry operation (add, move, resize, nest) its absolute place and size; it does not repeat the type, the label, a missing parent or the four default connection points (`inspect_diagram` leaves those out too, and gives styles only when asked). Problems of one kind, when there are more than three, become one line with their number, three examples and the elements involved. The layout check also finds a label that does not fit its box, using the export's own text wrapping ([ADR 0124](0124-svg-export-from-a-shared-pure-renderer.md)).
- **Not covered:** icons, reference images, the security matrix, gravity presets and edge direction sets. They go through the raw file tools.

## Alternatives considered
- **A compact description the tool turns into a diagram** (like D2). It hides the step-by-step loop, leaves the assistant guessing at the result, and needs placement the tool would have to decide.
- **Helper functions the assistant calls from its own script.** Small, but still needs a shell and a runtime.
- **Only the running app executes the operations.** Watching it happen and undo come for free, but the app must be open and the connection needs its own security design.

## Consequences
- A second path for edits that must produce what the editor would: every result is validated and written in the app's own serialisation, and the tests check both.
- The command line runs the same operations: `chd edit` and `chd ask` ([ADR 0150](0150-chd-edit-and-chd-ask-build-a-diagram-from-the-command-line.md)).
- The set of style fields is checked in the core (known fields, numbers in range, known markers) and passed through to the file.
